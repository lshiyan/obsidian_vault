- MAIN IDEA: An AI system can be optimized directly from the execution traces that are produced as part of its rollout.
- GRPO is a popular way to optimize LLMs for downstream tasks, but it requires a large number of rollouts that are inefficient practically. However, these rollouts are essentially just natural language documents, and as such we can leverage the strong language priors of most LLMs in order to reflectively optimize their own prompts.
- Our setting is any arbitrary compound AI system, which consists of potentially many LLM modules, tool calls, and some control flow. The system is defined as $(M, C, X, Y)$, where $M = (M_1 ...)$ is the set of all LLMs, $C$ is some control flow logic, and $X, Y$ denote global input/output schemas. Each module $M_i$ is an LLM with $\pi_i$ being its system prompt and $\theta_i$ being its weights. The learnable parameters are the set of all system prompts and weights $(\Pi, \Theta)$. The optimization problem is then $\arg\max_{\langle \Pi, \Theta \rangle_\Phi} \mathbb{E}_{(x,m)\sim\mathcal{T}} \mu\left(\Phi(x;\langle \Pi,\Theta\rangle_\Phi),m\right)$, where $(x,m)$ are a task instance with evaluation metadata, $\mu$ is some metric that measures the output of the task $x$ with respect to $m$, and $\mathcal{T}$ is the task distribution. We also want to limit the number of rollouts to reduce complexity.
- GEPA does not actually change the weights of the LLMs, only the prompts themselves $\Pi$. We start off with a candidate pool $P$, where each candidate is a concrete initialization of the prompts. Given a candidate, we roll it out on a minibatch of training examples. We extract the execution trace, and use a reflection LM to iteratively update the prompts of a specific module based off of the scores that are seen. If the scores improve, then the new prompt is added to the candidate pool.
