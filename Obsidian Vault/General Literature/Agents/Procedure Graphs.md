- PG's are objects that represent information about how agents can accomplish tasks. They are similar to knowledge graphs in the sense that they represent information about what an agent should do given its state in triplets.![[Pasted image 20260914132600.png]]
- The PG is $G = \langle V, R, E, \Phi \rangle$, the $V$ represents the nodes, the $R$ represents a vocabulary of relations, and $E \in (V \times R \times V)$ is an edge in the graph. The $\Phi$ stands for an attribute mapping that associates each edge with a named set of attributes.
- At inference time, we freeze the graph and use it to generate a procedure. Given a query prompt $q$, we first find the node that best represents our current state using a trajectory of prior actions $u_t = Match(a_{t-1}, V)$. We then expand the current node $u_t$ into a subgraph of degree $h$ using, or use the full graph if we cannot find a matching node $G_t = N_h(u_t)$. We then use this graph to generate a guidance prompt as follows $g_t = \Psi(G_t, q, T_{t-w:t})$, where we use $w$ prior steps of the trajectory $T_t$. This guidance prompt is then appended to our task solver's prompt in order to refine its action decision.
- Offline, they sequentially improve the graph. Given a graph $G_{k-1}$, they first evaluate it on a set of tasks $B_k$, recording the trajectories and final score for each. Given the trajectories, they use an LLM refiner in order to either add or delete nodes / edges from $G_{k-1}$. They keep this graph if the mean score on a held out validation set exceeds the mean score from the retained graph $G_k$. Additionally, they store any non-accepted edits into memory $H_{rejected}$, such that repeatedly rejected edits will not be allowed to be proposed again by the refiner.
